# Soota

Use an installed `soota` command. For a source checkout, resolve this SKILL.md symlink, locate the repository two directories above its skill directory, verify pyproject.toml belongs to Soota, and run `uv run --project <repository> soota ...`. Do not hard-code a personal checkout path. Codex calls this CLI; Soota chooses its internal Providers. Do not register opencli-mcp as a separate Codex tool for this workflow.

In a managed LoreLab installation, use `lorelab tool soota -- ORIGINAL_ARGS` and locate the bound source with `lorelab doctor` / `lorelab skills list`. This Skill owns collection, parsing, context and acquisition recovery. It remains usable in an independent Soota installation without LoreLab.

For Soota development or CLI upgrades, read [maintenance](../../docs/maintenance.md). Source and this complete Skill have one editable home, LoreLab `modules/soota/`; the standalone repository is generated. Do not patch both copies or replace a managed CLI with a separately installed version.

Single-source analysis, notes, articles, outlines, classification review and bundle export belong to **LoreLab content and the LoreLab Skill**. Knowledge/study delivery and authorized cleanup also belong to LoreLab. Locate it through `lorelab skills list` when installed; do not recreate that workflow here. Old `soota knowledge/study` commands only forward to LoreLab and are hidden from ordinary help. Old semantic/export ingest requests, semantic/delivery job resumes and `soota render` also forward through hidden compatibility bridges that dynamically call LoreLab in the same Python environment, without selecting another executable from PATH. Missing LoreLab must be reported before modifying a task, budget or artifact. Existing task IDs/paths, source evidence, budgets, artifacts and configuration remain readable through LoreLab; the old `lorehub` command is removed.

## Choose the requested output

For a new acquisition goal expressed in conversation, first normalize the requested input, required/optional outputs and constraints, then use `plan create INPUT --goal "SHORT_GOAL" --want TARGETS --json`. Read [planning and presets](references/planning.md). Present the returned alternatives and price limits. Matching presets are proposals: ask whether to reuse them, and only pass `plan select ... --confirm` after the user chooses. Selection saves the named preset; `plan run` uses the existing executor. Never infer confirmation from elapsed time or a match. Explicit direct CLI requests and existing job recovery may keep their existing entry points.

Use `ingest INPUT --want ... --json` for explicit artifacts and combinations: `video`, `audio`, `transcript`, `context`, `markdown`, `images`, `data`. `--optional` declares outputs whose failure does not block the required ones. Inputs can be URLs, local files, a bundle directory or manifest, and `--inputs-file` lists. For batch processing, existing bundles, explicit native operations or acquisition recovery, read [task workflow](references/tasks.md).

Unified tasks accept `--workers 1..8` (default 1). Start with the requested bound, or a small bound such as 2 for an authorized batch; enumeration and result ordering remain stable. Resume retains the saved bound unless overridden. All workers share one durable budget; increasing concurrency does not increase the cap. Ctrl-C drains started workers before releasing the job lock, so shutdown can take until provider timeouts.

Default collection ends at unprocessed context. Saving an existing article uses `context` or `markdown`; a requested semantic article uses `lorelab content ingest --want article`. Do not introduce an article step before a summary or analysis. A media-only request does not authorize transcription or summarization; do not load the full body for a download-only request.

For requested saved analysis, notes, articles, outlines or export, hand the returned source bundle to LoreLab content and follow its Skill. For knowledge articles and study delivery, use LoreLab knowledge/study. Pure collection or a summary-only request does not authorize knowledge-base writes, cloud delivery or deletion. Preserve the source bundle, task/item identities and context fingerprints for downstream use.

The existing single-video command without `--want` remains available: `ingest URL --transcript captions-only|auto|asr|none --json`. Use `inspect URL --json` for metadata only. Use `doctor --json` when required runtimes are unknown.

Local ASR checks audio-track EOF and repetition before accepting a transcript. `asr_quality_rejected` includes flags and a separate raw diagnostic path; never silently trim timestamps/words or treat rejected output as complete. Empty recognition does not establish absence of speech. Inspect track presence/energy, distinguish music from speech, and check the requested language; independent local recovery must preserve old artifacts and provenance. Do not download models or call an external model without authorization. See [local engine and recovery guidance](../../docs/terminal-tutorial.md#本地转写引擎).

For optional X/Reddit body acquisition, Weir supports `ingest URL --provider weir --want context` (or `context,markdown,data`). Read [Weir limits](../../docs/weir.md) before enabling it. It is disabled by default and only supports free workspaces; never turn on paid use. Configure monthly/default task credits with `providers limits weir`; `--weir-max-credits` is a task total retained on resume. Do not guess limits, erase uncertain reservations, or use a balance snapshot as proof of atomic free-only billing. No top-ups during a free-only run. Named backups use `providers auth weir --key-name NAME`; inspect/enable/disable them with `providers keys weir`. New data calls use durable ordered round-robin, and only a confirmed 401 skips to the next key within that call; insufficient balance, rate limits, upstream errors and uncertain billing stop. All keys share the UTC calendar-month cap and durable task total. `WEIR_API_KEY` exclusively overrides the entire file pool. It does not provide search, comment/thread enumeration or media downloads through this integration.

An extra balance is not automatically purchased or gifted. If the user explicitly confirms it is a free gift, record `providers gift weir --key-name NAME --credits N` for that current key; otherwise preserve the refusal. The confirmation only permits that bounded gift balance to coexist. Requests still require enough monthly `freeGrant.remaining` after holds, and keep the free-tier, task and monthly limits. A new key does not inherit a previous confirmation; use `--credits 0` to revoke it.

## Acquisition and failures

Windows core commands, durable task locks and UTF-8 records are supported. Downie, Keychain and MLX remain Mac-only. External yt-dlp media downloads and FFmpeg extraction/muxing currently stop before dispatch on Windows because a hard file-size cap cannot be enforced; existing media verification, bounded HTTP files and captions remain available. Report this limitation and preserve required targets and budgets; do not bypass it with an unbounded external command. See [task workflow](references/tasks.md).

Video captions follow saved platform/capability cost or manual priorities. Free sources precede paid sources by default; optional Monid uses Apify for YouTube captions; optional treg defaults to Crawl4AI, with configurable ScrapeCreators. Both relay only explicitly supported TikHub contracts. Online execution refreshes expired/missing quotes (24-hour default), shared across task stages and workers; failed refresh never authorizes use of stale prices. Use `providers auth/enable/disable` and `providers priority set/show`; quote full request chains, not unrelated endpoint prices. Read [provider configuration](references/providers.md) for CLI examples. Confirmed missing tracks end the caption chain: `auto` obtains audio and transcribes locally, while `captions-only` stops without ASR. Empty responses, unknown states and login failures are not proof of absent captions. `asr` explicitly requests transcription. Missing timestamps stay unknown; do not invent timed exports or apply timed filtering to untimed text.

Comments and danmaku are not captions. Bilibili `ai-*` tracks are automatic subtitles, acquired with ordinary subtitle flags. Legacy `--provider soota` remains a yt-dlp alias; new results identify `yt-dlp`.

`--provider` selects the source strictly; common local conversion and verification do not change that source. For ASR audio, `--audio-provider yt-dlp` is the default, `downie` is opt-in on macOS and needs the completion hook, and `tikhub`/`monid`/`treg` require payment authorization. `--audio-provider auto` uses the audio priority rule. Empty subtitle results can still be billed; Monid receipts record upstream, runId and reported actual cost. Monid resumes pending runs without a second submit. treg completed receipts are reused within the original task; uncertain/202 results remain blocked for manual reconciliation, without automatic resend or polling; never erase a task reservation to retry. TikHub audio failure does not authorize a new yt-dlp acquisition. A `download_pending` result is unfinished: inspect the original task and resume without resubmitting a Downie download.

`--max-cost 0` blocks billed requests. Unified batch jobs share durable reservations, including enumeration and later audio requests; resume does not reset them. In ask mode, noninteractive paid calls stop with `payment_required`. Do not bypass that gate or enable automatic payment for the user. Login, permission, rate-limit, timeout and contract errors do not authorize blind retries or manual paid fallback.

For OpenCLI failures, inspect the safe `details.category/reason/upstream_code/exit_code/retryable` and fixed `hint`; never copy raw stderr or signed links into shared logs. Soota does not automatically replay commands. A known transient free read may be resumed explicitly after checking all unfinished job items; `jobs resume` does not select only retryable items. Xiaohongshu note reads require a signed URL from normal search/author-page navigation; do not invent tokens. A bound `twitter/thread` read must contain the requested post ID; adjust an insufficient explicit limit in a new task, without treating a parent post as the source. See [recovery](references/tasks.md#continue-a-saved-task).

MCP is disabled by default; do not enable, discover or start it for an ordinary task. `capabilities --json` inspects local capabilities without querying websites or checking login. Distinguish discovered/native/standard capabilities from actual site and artifact verification. A listed command does not imply standard content, media or collection support. For broader API queries, read [API reference](references/api.md); for catalog pagination and incremental snapshots, read [catalog reference](references/catalog.md).

## Optional subtitle selection

For requested Bilibili → YouTube counterpart selection, use `--prefer-youtube`; `--no-prefer-youtube` disables it. This requires same-author and same-episode evidence. Do not claim verified creator identity when `author_crosslink_confirmed` is false. Read `selection` / `youtube_check` for the actual choice.

This option also enables promotion filtering; `--keep-promotions` overrides it. `--exclude-range START_SECONDS:END_SECONDS` removes independently reviewed intervals, retaining original times and stable segment IDs. Review unannotated ads when the user asks for promotion-free output; absent annotations do not prove absence. Changed filtering may require a new output folder or authorized source replacement. See `docs/subtitle-selection.md` for current restrictions.

## Results and downstream use

`--json` prints one status document. For unified jobs, inspect `job_status`, `items`, each item's missing outputs, errors and artifact paths, plus enumeration completeness and reserved cost. Report actual files and Providers; successful enumeration or one completed step does not mean every requested artifact is complete. A passed file hash does not establish full-length media when source duration is unknown.

Read `data.context` or the item's context path as the Agent input. `transcript.md` retains timestamped evidence; v2 body blocks provide paragraph IDs. Old bundles without context can use `transcript.md`. The legacy ingest `data.content` remains a compatibility alias for context. `source_preserved` means the current attempt did not replace an existing valid source; do not call it fresh acquisition.

For a historical `waiting_analysis` or delivery task, use `lorelab content resume` and the LoreLab Skill. Preserve the task/item identity, source evidence, current context fingerprint, original paths and budget. Soota new collection tasks do not create semantic handoffs. Legacy TaskSpec targets and AnalysisManifest states are data compatibility only, with no semantic generation or export implementation. LoreLab preserves existing analysis-request bytes when task/item identity, context fingerprint and requested outputs match, retaining frozen hashes. [Analysis migration](references/analysis.md) describes the compatibility boundary; do not mark a task complete merely because a handoff exists or generate unrequested content because old metadata is stale/pending.

## Destinations and local rules

Before saving source artifacts in a user-selected collection, read its applicable `AGENTS.md` and relevant source-retention and sync rules. `--output` selects the source-bundle location. Explicit bundle export, `--destination` / `--vault` / `--subdir`, semantic writing and knowledge classification are handled by LoreLab content and its Skill; never guess a private vault path or rebuild those workflows in Soota.

Use collection display names for reading labels; preserve CLI-managed bundle paths, source IDs and manifest fields unless the task explicitly includes a compatible migration.

Keep personal paths, browser choices, credentials, creator lists and prompts in user-owned configuration or collection files. Supported environment variables include `SOOTA_OUTPUT_DIR`, `OPENCLI_PROFILE`, `SOOTA_YTDLP_BINARY`, `SOOTA_YTDLP_COOKIES_BROWSER`, and `TIKHUB_API_KEY`; never embed actual values in the Skill or project. Do not put cookies or keys in chat or command arguments. Project-external files can still be synced or Git-tracked; check the destination's own rules. Soota does not automatically manage watchlists, schedule collection or reorganize a knowledge base.

Online collection/API commands update published provider packages by default; inspect `runtime_updates` and warnings. Help, offline plans and local processing do not need a website update check. `updates check` is read-only; `updates apply` is an explicit update. Updating MCP does not enable it. `SOOTA_AUTO_UPDATE=false` preserves a pinned runtime. yt-dlp and Downie are updated separately. Package availability and compatibility checks do not prove a website works.
